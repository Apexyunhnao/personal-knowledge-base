# 知识库项目面试话术速查（2026-08-29）

> 用途：作品集面试讲 rag-qa 项目。数字全是真实评估值，可放心说。
> 原则：讲「检索质量 + 评估体系 + Agent 接入」，不讲「我攒了 2 万条数据」。

## 30 秒版本（背熟）

我做了一个个人决策知识库，把 2.3 万张方法论和经验卡片，用 SQLite 全文检索加向量检索双路召回、RRF 融合，做成一个「决策提醒系统」——它不是一个聊天机器人，而是检索到对的卡片帮用户做判断。我建了 57 条真实场景的对抗集做持续评估，Hit@10 达到 94.2%，负样本零误召。这个系统已经通过 MCP 接入了 Hermes Agent 作为外部记忆，可以让 Agent 自己检索和存入知识。

## 60 秒版本（含技术点）

我这个项目解决的核心问题是：个人做重大决策时，最缺的不是信息，而是经历过类似困境的人留下的方法论。所以我把书、经验帖、攻略文萃取成结构化的方法论卡片，核心是让「对的卡片出现在检索结果前 10 名」。

技术上有三个点：
第一，混合检索。SQLite FTS5 做关键词精确匹配，bge-small 中文向量做语义匹配，两路结果用 RRF 融合——因为两路的分数空间不一样，直接加权不可靠，按排名融合更鲁棒。
第二，质量控制。标签加权、来源权重（书比论坛可信）、低置信度过滤，防止低质量卡污染召回。
第三，评估闭环。我收集了 57 条真实场景 query，覆盖 8 个板块加 5 条负样本，用 DeepSeek 逐条判定相关、部分相关、不相关，算 Hit@10、MRR，每轮迭代跑分有历史基线。

最终效果：Hit@10 94.2%，MRR 0.728，负样本 66% 拒绝率。整个系统接入了 Hermes Agent 的 MCP，Agent 可以直接检索和写入知识。

## 一句话总结（简历/项目介绍用）

「面向个人决策支持的 RAG + Agent Memory 系统：混合检索 + 对抗集评估闭环 + MCP Agent 接入」

## 面试官必追问 + 应对话术

### Q1: 为什么不用纯向量检索？
**答**：纯向量对语义相近但关键词明确的场景不稳定。决策类 query 往往有明确关键词（比如「止损」「试用期」），FTS5 精确命中更稳；纯 FTS5 又抓不住语义。所以双路召回，RRF 融合。

### Q2: 为什么用 RRF 不用 score 加权？
**答**：FTS5 和向量检索的分数范围、分布完全不同，直接加权需要调两套权重，很脆。RRF 只看排名，1/(k+rank) 融合，鲁棒、不用调参。

### Q3: 严格相关率为什么只有 33%？
**答**：这是判定口径。卡片是「方法论提醒」不是「直接答案」——比如问「怎么治拖延症」，卡片给的是「把任务切成 20 分钟门槛」这类方法，判定模型觉得是 partial 不是 relevant。我的产品定位就是决策提醒，不是问答机器人。可用相关率（relevant+partial）是 76.6%。

### Q4: 最近指标为什么波动（81.5→79.4）？
**答**：加了 109 张新板块卡片后，新卡挤占了部分旧 query 的 top10，属于新数据入库的排序变化。我做了逐 query 对比，定位到是职场类新卡挤占，不是检索核心退化。这本身就是评估闭环的价值——能定位到具体原因。

### Q5: 天涯帖数据会不会过时？
**答**：会。所以下一步规划时效治理——给卡片加 source_year、valid_until，检索时对时间敏感类目降权或提示。人性经验类内容跨周期，但职场政策、市场判断类需要时效标记。

### Q6: 这是不是 ChatGPT 套壳？
**答**：不是。聊天不是核心产品，检索才是。系统目标不是让 LLM 编一个合理回答，而是在真实决策场景里召回有依据的卡片，再由 Agent 利用卡片辅助判断。LLM 只做两件事：卡片萃取和评估判定，都可有可无——检索层是核心。

### Q7: 数据版权怎么处理？
**答**：完整库本地自用。公开仓库只含代码和评估数据，不含书籍原文。萃取产出的是方法论卡片（二次创作），不是原文搬运。

### Q8: 为什么只测 Hit@10？
**答**：Hit@10 回答「能不能找到答案」，MRR 回答「正确的排得多靠前」，我两个都测了。nDCG 是下一步计划。

## 讲项目的顺序（STAR）

1. **S 场景**：个人做决策缺方法论，不是缺信息
2. **T 任务**：做一个检索到「对的卡片」的决策知识库，不是聊天机器人
3. **A 行动**：混合检索（FTS5+向量+RRF）→ 质量控制（加权+过滤）→ 评估闭环（对抗集 57 条）→ MCP 接入
4. **R 结果**：Hit@10 94.2%、MRR 0.728、负样本 66% 拒绝、v1→v16 基线迭代

## 避坑

- ❌ 不说「我攒了 2 万条数据」——像数据搬运工
- ❌ 不说「我的 RAG 很准」——没依据
- ❌ 不主动提《做空次贷》这类低价值版权数据
- ✅ 主动提短板 + 优化方案（人际博弈 67% → 缺 playbook 卡 → 补操作型 schema），比被追问强
