# 萃取步骤验证错误流程（Pipeline Gate）

> 用途：任何"导出→萃取→入库→复测"任务必须逐步骤过检查点。每步失败有明确处理路径，不带着问题往下跑。
> 适用范围：微信读书导出 / ttkan 爬取 / 批量萃取 / 入库 / 对抗集复测。
> 原则：**每步验证过才进下一步；失败先止损（备份/回滚），再修，不硬推。**

---

## 步骤 0：输入检查（开工前）

| 检查点 | 方法 | 通过标准 |
|---|---|---|
| 0.1 书 hash 正确 | curl reader 页面看章节数 | 章节数 > 0，标题是目标书 |
| 0.2 版本正确 | 对照 title+author | 不是同名其他版本（搜索带作者名） |
| 0.3 cookie 有效 | curl 带 cookie 返回 200 | 能读到完整章节（wordCount 正常） |
| 0.4 目标 query 明确 | 列出要覆盖的评估 query | 知道这书为哪些 query 服务 |

失败处理：0.1/0.2 → 重新取 hash（deepLink v= 参数，勿截断）；0.3 → 跑 weread_login.py 重登，写回 WR_SKEY；0.4 → 先拆 query 类型再选书。

---

## 步骤 1：导出验证（Playwright 抓取）

| 检查点 | 方法 | 通过标准 |
|---|---|---|
| 1.1 章节数完整 | ls *.md 数 vs wordCount 目录章节数 | 差 ≤ 1 章 |
| 1.2 内容量达标 | 导出总字数 vs 页面 wordCount | ≥ 80%（防试读残缺） |
| 1.3 每章字数正常 | 抽查 3 章字数 | 与 wordCount 单章量级一致（不是 100-200 字/章） |
| 1.4 内容连贯 | head 1 章正文 | 无乱码、无左右页交错、段落完整 |

失败处理：
- 1.1/1.2/1.3 字数少 → **cookie 失效/未登录**（只渲染试读）→ 重登 → **rm -rf 旧输出**（幂等按标题去重会把残缺章 skip）→ 重导
- 1.4 乱码 → 双页交错 bug → 修 CANVAS_HOOK 的 cid 分组 → rm 重导
- 浏览器被手动关 / TargetClosedError → 重跑即可（断点续传）

---

## 步骤 2：normalize 验证（md → txt）

| 检查点 | 方法 | 通过标准 |
|---|---|---|
| 2.1 txt 数量 | ls inputs/<书>/*.txt | == md 章数 |
| 2.2 标题正确 | head 第 1 个 txt | 首行是真实章节名（不是乱码/空） |
| 2.3 正文可读 | head 20 行 | 无残留 markdown 符号、无乱码 |

失败处理：2.1/2.2 → normalize 脚本参数（位置参数：`normalize_weread.py <md目录> <书名>`，不是 --book）；2.3 → 检查导出质量，回步骤 1。

---

## 步骤 3：萃取验证（LLM 卡片生成）

| 检查点 | 方法 | 通过标准 |
|---|---|---|
| 3.1 产出量 | ls outputs/<书>/*.json | 在预期范围（如 100-200 卡） |
| 3.2 卡片质量 | **抽检 15-20 张**（随机） | ①标题有信息量（不是"危机中要小心"）②内容保留事实/机制/数据 ③无空泛方法论 ④无幻觉事实（对照原文） |
| 3.3 标签规范 | 抽查标签 | 精准实体标签（明斯基时刻/次贷危机/现金避险），无泛标签（金融危机） |
| 3.4 标题长度 | 统计 | 多数 ≤ 20 字 |

失败处理：
- 3.2 空泛（四步法洗稿症状）→ **换 prompt**（概念/案例复盘卡）→ 清 outputs 重萃（--limit 2 先试跑验证）
- 3.2 幻觉事实 → 检查书章节是否被截断（回步骤 1）；模型反复错 → 换模型/降温
- 3.3 标签泛 → 改 prompt 标签指令

---

## 步骤 4：入库验证（import_to_kb）

| 检查点 | 方法 | 通过标准 |
|---|---|---|
| 4.1 入库数 | import 日志"新建 N" | N == 预期（--dry-run 先看） |
| 4.2 库总量 | SQLite COUNT | 总量增加 == N |
| 4.3 向量同步 | chroma count == SQLite count | 相等（不一致 → 重启服务重建） |
| 4.4 无误合并 | 对比 --dry-run 合并数 | 合并数 0（--no-merge 强制） |

失败处理：
- 4.1 少 → 看日志哪章失败 → 单章补跑
- 4.3 向量不一致 → 全量重建（10-30 分钟）或 sync 增量
- 4.4 大量合并 → 恢复备份（入库前必须备份 personal.db），改参数

---

## 步骤 5：效果验证（对抗集复测）

| 检查点 | 方法 | 通过标准 |
|---|---|---|
| 5.1 目标板块提升 | judge 对比 | 目标板块 ≥ +3pp（如金融危机 60→63+） |
| 5.2 无劣化 | judge 对比 | 其他板块波动 ≤ 3pp（LLM judge 噪声区间） |
| 5.3 负样本 | judge | 拒绝率不显著下降 |

失败处理：
- 5.1 没提升 → 看目标 query 检索结果（内容在不在/被什么挤掉）→ 判断"内容缺失"还是"检索错位"→ 换书 or 改检索（backfill_op_tags 模式）
- 5.2 劣化 → 新卡污染（标签泛/内容无关）→ 回滚这批卡（备份恢复），收紧标签
- **多轮 judge 波动**：单次 ±3pp 是噪声，连跑 2 次看趋势，不因单次结论调权重

---

## 回滚总则（任何步骤发现不可逆损坏）

1. 数据库操作前**必须**备份：`sqlite3 backup` 到 backups/personal_before_<操作>_<时间>.db
2. 回滚 = 恢复备份 + 重启服务 + 向量重建（如果备份点之前向量一致则跳过）
3. 改了萃取 prompt / 抓取逻辑 → 对应 outputs/ 必须清空重跑（幂等会 skip 旧产物）

## 快速核对命令（Windows 环境）

```bash
# 导出量
ls <md目录>/*.md | wc -l
wc -c <md目录>/*.md | tail -1
# 卡数
ls outputs/<书>/*.json | wc -l
# 库总量 + 向量
sqlite3 personal.db "SELECT COUNT(*) FROM learning_notes WHERE deleted_at IS NULL"
# chroma 向量数（rag-qa-venv python）
python -c "import chromadb; c=chromadb.PersistentClient('chroma_db'); print(c.get_collection('notes_knowledge').count())"
```
